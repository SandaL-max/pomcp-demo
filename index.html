What to notice

  1. The action changes with belief. Near 50/50, POMCP listens. As the belief sharpens, its root value for opening a door overtakes listening and it commits.
  2. The exact planner is the benchmark. The badge tells you whether POMCP’s sampled action matches the optimal action for the same belief. Sampling noise causes occasional disagreement — and the occasional −100.
  3. More simulations, more stable values. Drag simulations down to 500 and watch the Q-values wobble. The tree is an anytime approximation.
  4. Information has a price. Each listen costs 1. Lower the discount or the listen accuracy and the planner becomes more willing to gamble.

The algorithm

How POMCP thinks

POMCP combines a particle filter, a generative model, and Monte-Carlo tree search. The tree is indexed by action–observation histories, so each node implicitly represents a belief.

01

Believe with particles

A belief is a set of sampled states. After acting and observing, propagate each particle through the transition model, reweight it by how likely the observation was, and resample.

b′(s′) ∝ O(o | s′, a) ∑s T(s′ | s, a) b(s)
02

Sample the future

The environment is a black-box simulator. From a particle, POMCP samples transitions, observations and rewards. At a new history it falls back to a random rollout.

(s′, o, r) ~ G(s, a)
03

Grow a history tree

Each node is a history h. UCT selects actions, observations branch the tree, and the mean return is backed up along the visited path.

a* = argmaxa [ Q(h,a) + c √( log N(h) / N(h,a) ) ]
04

Act, observe, replan

After executing the best root action, the subtree for the received observation becomes the new root. Planning continues online at every step; no policy is ever stored offline.

h ← h · a · o    then sample more simulations
POMCP, stripped down Silver & Veness (2010) 
# choose an action from the current belief
for i = 1 .. N:
    s ~ B(h)                    # sample a particle
    Simulate(s, h, 0)
return argmax_a Q(h, a)

function Simulate(s, h, d):
    if h ∉ T:
        T[h] ← new node
        return Rollout(s, d)     # random playout

    a ← UCT(h)
    s′, o, r ← G(s, a)
    R ← r + γ · Simulate(s′, h·a·o, d+1)

    N(h,a) += 1
    Q(h,a) += (R − Q(h,a)) / N(h,a)
    return R

Why it works

POMCP replaces the intractable belief-state MDP with a sampled lookahead. Because every simulation starts from a state drawn from the current belief, the root values average over uncertainty. Because observations branch the tree, the planner can reason about future information: “listening now is worth it because it will let me choose the right door later.” Tree reuse after each step turns one long planning problem into many small, warm-started ones.

It is a Monte-Carlo method: finite simulations mean noisy values. The demo’s exact planner shows the action an oracle would pick for the same belief, which makes POMCP’s approximation error visible instead of hiding it.

This demo

The planner and Tiger model are a dependency-free JavaScript implementation of POMCP. The exact benchmark is value iteration on a 501-point belief grid. A separate reference implementation in Python mirrors the same algorithm.

index.html · UI js/pomcp-core.js · planner + particle filter js/tiger.js · model + exact solver python/pomcp.py · reference implementation

Built as a teaching demo. No external libraries, fonts, or network calls. The tiger problem is used with an episodic twist: opening a door ends the episode, so a wrong open is a single catastrophic outcome rather than a reset.
